## 1. Core Vision & Product Principles

AI Placement Analyzer compares a user's resume against a target job description (JD) using deterministic skill matching, semantic similarity, evidence-based retrieval, and an LLM to deliver explainable match scores, prioritized skill gaps, resume improvement suggestions, learning roadmaps, and role-specific interview questions.

1. **Evidence-First:** Every important recommendation must trace back to retrieved resume/JD evidence or clearly identified external learning guidance.
2. **Transparent Scoring:** Match scores are calculated strictly by deterministic application logic, never generated by an LLM.
3. **No Fabricated Experience:** The AI must never invent skills, projects, achievements, or work experience.
4. **Abstention Over Guessing:** When context is insufficient, return `insufficient_evidence` instead of guessing.
5. **Privacy-First:** Resumes contain sensitive PII and must be stored privately, protected by RLS, and deletable on demand.
6. **Build Order Rule:** Build the deterministic foundation (parsing, normalization, matching, scoring) first; layer on RAG and LLM features only after structured data and matching are reliable.

## 4. Architectural Decision Records (ADRs)

* **ADR-01 — Deterministic Match Scoring:** Match scores are computed exclusively in backend logic using weighted requirements (`Matched = 1.0`, `Partially Matched = 0.5`, `Missing = 0.0`) with the formula:

  $$\text{Match Score} = \left(\frac{\sum \text{Earned Weighted Requirements}}{\sum \text{All Weighted Requirements}}\right) \times 100$$

  Descriptive labels (`80–100` Strong, `60–79` Moderate, `40–59` Partial, `0–39` Low) never imply guaranteed hiring probability.
* **ADR-02 — Hybrid Skill Normalization:** Skills are normalized via a canonical dictionary (`public.skills`), alias mapping (e.g., `JS` -> `JavaScript`, `ReactJS` -> `React`, `Node JS` -> `Node.js`), and categories first. Semantic matching is strictly secondary and must never merge unrelated skills (e.g., `Java` vs. `JavaScript`).
* **ADR-03 — Hybrid RAG (`pgvector` + Full-Text Search):** `document_chunks` combines `pgvector` HNSW cosine similarity with PostgreSQL `tsvector` FTS via Reciprocal Rank Fusion (`hybrid_match_document_chunks` RPC) so exact technical acronyms (`C++`, `JWT`, `SQL`, `AWS S3`) are never missed. Chunks below similarity thresholds (`0.55` hybrid / `0.65` semantic) are dropped; zero qualifying chunks triggers an immediate abstention (`missing` / `insufficient_evidence`).
* **ADR-04 — Untrusted Document Isolation & 3-Stage Verification Gate:** Retrieved resume and JD chunks are wrapped in `<untrusted_resume_chunks>` and `<untrusted_jd_chunks>` XML tags with strict prompt-injection instructions. Every LLM JSON response must pass: (1) Zod runtime schema validation, (2) programmatic `chunk_id` + verbatim quote verification against supplied context, and (3) max 1 repair retry before gracefully falling back to deterministic results.
* **ADR-05 — Defense-in-Depth Security & RLS:** All 12 PostgreSQL tables enforce Row Level Security (`auth.uid() = user_id`). User-scoped backend queries pass the verified Supabase JWT; `SUPABASE_SERVICE_ROLE_KEY` is restricted to trusted server-side workers and account deletion, always filtering explicitly by verified `user_id`.
* **ADR-06 — Asynchronous Analysis Pipeline:** `POST /api/v1/analyses` returns `202 Accepted` and transitions through `queued` -> `processing` (`skill_matching`, `evidence_retrieval`, `ai_analysis`, `validation`) -> `completed` / `failed`. The frontend polls `GET /api/v1/analyses/:id`.
* **ADR-07 — 5-Layer Testing & AI Release Gates:** PRs run offline unit tests + local Supabase integration/RLS tests using `mockAIProvider`. Staging and prompt changes must pass `npm run eval:ai` across all 13 mandatory PRD evaluation scenarios.

## 5. Non-Negotiable Engineering Guardrails

1. **Never** let the LLM calculate or override the numeric match score or skill weights.
2. **Never** recommend fabricating experience, skills, projects, or achievements. Resume suggestions must be tagged (`improve_wording`, `highlight_existing_skill`, `acquire_new_skill`).
3. **Never** trust client-supplied `user_id`—always derive identity from verified `req.user.id`.
4. **Never** expose `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, internal stack traces, or public resume URLs.
5. **Never** trust file extensions alone—validate magic bytes (`%PDF-` / DOCX OOXML), enforce a 10 MB cap, reject encrypted/scanned PDFs, and store files at `{user_id}/{resume_id}.{ext}`.
6. **Never** log full resume contents or PII—log only `request_id`, status codes, and timings. Redact phone, email, and address from chunks before sending context to AI providers.
7. **Always** preserve the original uploaded resume file and raw extracted text for evidence verification, allow users to review/edit parsed profiles, and support cascading deletion of resumes, analyses, and accounts.
8. **Build Phases 1–4 before Phase 5:** Do not wire embeddings or Gemini LLM calls until parsing, normalization, and deterministic scoring pass unit and integration tests.

## 7. Core Schema, API & UI Quick Reference

* **12 PostgreSQL Tables (RLS-Protected):** `profiles`, `skills`, `resumes`, `resume_profiles`, `resume_skills`, `job_descriptions`, `job_requirements`, `analyses`, `analysis_skill_matches`, `document_chunks`, `interview_questions`, `learning_roadmaps`.
* **Versioned REST API (`/api/v1`):**
  * System & Profile: `GET /health`, `GET/PATCH/DELETE /profile`, `GET /dashboard/summary`, `GET /skills`
  * Resumes: `POST/GET /resumes`, `GET/PATCH/DELETE /resumes/:id`, `POST /resumes/:id/reprocess`
  * Job Descriptions: `POST/GET /jobs`, `GET/PATCH/DELETE /jobs/:id`
  * Analyses: `POST/GET /analyses`, `GET/PATCH/DELETE /analyses/:id`, `POST /analyses/:id/retry`
  * AI Generators: `POST /analyses/:id/{interview-questions | roadmap | resume-suggestions}`
* **14 Required UI Pages:** Landing, Sign Up, Login, Dashboard, Resume Upload, Resume Review, JD Input, Analysis Loading, Analysis Results, Skill Gap Details, Interview Preparation, Learning Roadmap, Analysis History, Profile & Settings.
